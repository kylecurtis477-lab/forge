# Forge build plan

This is the plan to execute, in phase order. It merges the open items from docs/SYSTEMS.md (roadmap items 1–9), the compiler performance list, and six pillars:

- **A. Provable safety.** Forge is memory-safe by default:
  - ownership/borrow or region checking;
  - bounds checks, with elision where they can be proven unnecessary;
  - no null;
  - `unsafe` blocks that are checked.

  The OS uses capabilities, and everything runs sandboxed.
- **B. AI-native.**
  - A tiny, regular grammar.
  - Machine-readable diagnostics and a JSON AST.
  - Built-in test/verify tooling.
  - Later, an OS intent/command layer.
- **C. One language everywhere.**
  - Forge for the kernel, apps, and servers.
  - Generics, slices, a package manager, a stdlib, an LSP, a formatter, and DWARF.
  - Later, ARM64 and GPU backends.
- **D. Instant and seamless.**
  - Fast boot.
  - Reproducible, declarative system configuration.
  - A sandbox per app.
- **E. Auto-parallelism.** SIMD, parallel-for, and a multicore runtime.
- **F. Compatibility.**
  - A Linux syscall ABI layer that runs static Linux ELF binaries.
  - C and Python FFI.
  - Real hardware drivers: NVMe, AHCI, USB/xHCI, e1000/virtio-net, GOP.
  - Our own assembler and linker.

**Invariants for every phase:**

- `./build.sh` prints FIXPOINT OK.
- `./run_tests.sh` and `FORGEC_FLAGS=-O0 ./run_tests.sh` both report 0 FAIL. This includes the QEMU boot tests (kernel-wx, kernel-bios, kernel-uefi, efi-loader-gpt).
- Dual-boot rules hold:
  - install only into `\EFI\Forge\`;
  - GPT only, never taking over a whole disk;
  - the kernel only reads the disk until Phase 8 adds a separate Forge data partition, created only with explicit opt-in.
- Each deliverable is committed as soon as its test passes.

A phase is done when every listed test passes in CI (`run_tests.sh`) on both -O2 and -O0.

## Phase 2 — Never reboot: self-healing, live-updatable system (signature feature 1)
*This phase needs Phase 1's processes, services, and wait queues. Each sub-step is finished and tested before the next one starts.*
1. **Kernel module ABI.** Relocatable Forge modules (ELF ET_REL) are loaded and unloaded at runtime. They get a versioned symbol table and an explicit `init/exit/save_state/restore_state` contract. Test: load, call, and unload a module 1000 times with no leaks.
   - **Status: done.** `examples/kernel/module.fsi`; test modules in `examples/modules/` (forgec + `as` → `.ko`, shipped in `\EFI\Forge\mod\`). KABI 1.0: exports carry a since-minor; wrong major, newer minor, imports newer than the module's ABI, unresolved symbols and truncated images are rejected. Relocations R_X86_64_64/PC32/PLT32/32S with range checks; sections mapped W^X in 1 MiB slots at `0xFFFFFFFFD0000000`. Boot test: 1000 load/call/unload cycles, 0 frames and 0 heap bytes leaked, save/restore state across reload, 4 bad modules rejected.
2. **Drivers as isolated services.** Each driver (virtio-blk, tty/keyboard, later the network) runs as a user-mode or isolated service process. It reaches its device only through granted MMIO/IRQ/DMA capabilities and talks to clients over IPC. Test: injecting a crash into the driver service leaves clients alive.
   - **Status: done (virtio-blk).** `examples/kernel/drv.fsi` + `examples/user/blkd.forge`. The ring-3 `blkd` gets capability syscalls 400–407: port I/O checked against the device's 64-byte I/O window, MSI-X interrupt wait, one contiguous DMA region mapped into it, recv/reply IPC. `vb_read` (so FAT and all file I/O) is routed to it after a handover under `vb_m`. On driver death the kernel resets the device before the DMA frames are freed and fails the in-flight request with EIO. Boot test: init.elf read through blkd is byte-identical; a non-driver caller gets EPERM; an injected NULL write with a request in flight on the device kills blkd (#PF, exit 0x10e), the client gets EIO and continues, the kernel driver takes the device back, 0 frames / 0 heap bytes leaked. Gaps: no IOMMU (DMA not confined), one request in flight, tty/keyboard still in-kernel.
3. **Supervisor with automatic restart.** Death is detected, the service restarts with its saved state, and in-flight requests are replayed idempotently. Test: the boot test kills the block driver in the middle of `cat`, and the output is still byte-identical; the restart count is reported.
   - *Status: done.* For the whole shell session `blkd` runs under a supervisor kernel thread (`drv.fsi`). The boot script runs `crash 40` (syscall 408, a fault-injection hook) and then `sum` on the 96 KiB `\EFI\Forge\docs\big.bin`. blkd dies with a request in flight. The supervisor reaps it, respawns it from the cached image with its restart generation as an argument, and the kernel-held request journal replays the read. Replies are matched by sequence number, so a stale reply cannot complete a newer request. The FNV-1a hash of the file matches the one computed on the host, and the test reports "blkd restarts 1 … replayed 1". After 5 restarts the supervisor gives up and fails requests with EIO. The session leaks 0 frames and 0 heap. Gaps: the test file is read with `sum` (which hashes it) rather than `cat`, so the comparison is by hash; the device is the only driver state, and it is rebuilt on restart (there is no state blob to save); there is one request slot; writes are not replayed, since only reads exist.
4. **Hot-swap with state transfer.** Replace a running driver or module with v2. The old version quiesces, serialises its typed state, the new version restores it, and clients see only latency. Test: swap the tty driver while the shell is reading, and no keystroke is lost.
   - *Status: done.* The tty line discipline goes through three function pointers: push, lines and pop. v0 is built into the kernel, and `tty1.ko` (a 512-byte head+count ring) and `tty2.ko` (a 1 KiB ring with free-running indices, which recounts lines on restore) are interchangeable modules that share one state format. During the shell session a swapper thread cycles v1↔v2 every 2 ticks, and at the end it swaps back to v0. Each swap loads the new module, then, under rq_lock, saves the old state, restores it into the new module and switches the pointers. All tty calls run under rq_lock, so no CPU can still be in the old code when it is unloaded. If a restore fails, the swap is aborted. Boot test: about 120 swaps, about 40 of them with a partial line queued; pushed == consumed + erased, lost 0, dropped 0; no leaks. Gaps: the swap is triggered by a timer rather than by an operator command; the echo path is not part of the module. The fault-injection syscall 408 now returns EPERM unless the kernel's boot self-test has armed it for its shell session, and drv_test checks this.
5. **Live kernel patching.** Function-level patches are applied with stop-machine via IPIs. Each patched function gets a jump at its entry, verified by its hash. Rollback is supported. Test: patch `sys_getpid` while 4 CPUs hammer it; results switch atomically and rollback restores them.
   - *Status: done.* forgec (both `selfhost/forgec.forge` and the embedded `compiler.forge`) has a new `@patchable` decorator that emits a 5-byte nop (`0f 1f 44 00 00`) at the 16-byte-aligned function entry. `sys_getpid` is `@patchable`. `livepatch.fsi` registers the target, recording an FNV hash of its first 32 bytes. To apply a patch it checks the nop and the hash, then writes `jmp rel32` to the replacement in `getpid2.ko`. The write is a single aligned 8-byte store through the HHDM alias, so kernel text stays read-only. It happens under stop-machine: the other 3 CPUs are parked with interrupts off in the shootdown IPI and serialise with cpuid before continuing. Revert writes the nop back and re-checks the hash. `lp_apply_checked` tests the replacement before installing it (the wrong `lp_getpid_bad` is rejected and never becomes reachable), then tests the live entry point and rolls back if that fails. Boot test: 3 hammer threads on 4 CPUs make about 2.5 M calls while the patch is applied and reverted 25 times (about 1.5–1.9 M of the calls go through the patch); 0 wrong results; 1 rejection and 1 rollback; hash restored; patched code is not reached after rollback; 0 leaks; 6 back-to-back OS test runs passed after a stop-machine round-generation fix (a CPU that missed the release could get stuck into the next round). Gaps: only one patch site is tracked; the module is unloaded after a quiescence check based on the known callers (the hammers' loop counters plus an in-patch active counter), not a general stack walk; user processes call getpid through the same entry, but the test does not run them concurrently with the patching.
6. **kexec-style handoff (fallback).** Boot a new kernel image while keeping user state: process memory, fds, and the console are serialised into a handoff region the new kernel adopts. Dual-boot rules still apply, and nothing is written to disk. Test: the shell survives a full kernel replacement and the next command works.
   - *Status: done.* Syscall 409 (`kexec`, only when `ktest_hooks` is set, like 408) is in `kernel/kexec.fsi`. It pins the caller to the BSP (CPU 0) and sleeps until it runs there, so the successor's INIT-SIPI never hits a parked old BSP. It reads `\EFI\Forge\kernel.elf` from the read-only ESP, verifies it, and copies its PT_LOADs to a 2 MiB-aligned free physical range. It then builds a handoff region in free frames. The region holds: a header (magic, generation, brk, pid, FNV hash), a fresh BootInfo (`BOOT_KEXEC`, memory map with the region marked `MEM_HANDOFF`, saved RSDP copy), loader-style page tables, an identity-mapped jump stub, the FPU state, the syscall frame, args, and an index of every present 4K user page plus its data. To quiesce, it switches off input, resets virtio, masks the IOAPIC and LAPIC timer, and parks APs under stop-machine with `tlb_halt`, then jumps. The new kernel boots normally (its own ACPI/SMP/drivers), sees `bi.handoff`, checks the hash, rebuilds the process (pages, brk, args, console fds 0–2, FPU), and resumes it in a fork-style thread that returns 1 from the syscall. It then frees the region. Boot test (`boot.py`: `hello x`, `kexec`, `hello after kexec`, `exit`): the shell keeps its command counter across the swap (pid 52 → 34, 21 pages, 140 KiB region), runs the next command, and exits 0. `os/kexec-no-disk-write` checks the sha256 of the GPT disk image is unchanged after the efi-loader-gpt boot. All three boot paths pass, 3 back-to-back runs. Gaps: only the calling process survives (others, kernel threads, modules, and driver state are not carried over; drivers re-probe); only console fds survive; ACPI reclaim memory is no longer reclaimed so the successor can reparse tables; same kernel image (no version negotiation of the handoff format beyond the magic).
   - *Hardening (format v2):* `kexec next` (409 with arg 1) loads `\EFI\Forge\kernel-next.elf`, a genuinely different build (kernel/build.sh rewrites the version string to `forge-kernel 0.2.6-next` and fails if the ELFs are identical). The sender freezes every non-driver user process at a syscall boundary (syscall_dispatch entry, or inside the sys_wait / tty_read block loops; per-thread `sc[5]` records nr+args since the 80-byte frame lacks them), waiting up to 300 ticks, else prints "handoff abandoned" and returns EBUSY. Header v2 (448 B): magic, version, min/max accepted, sizes, counts, separate data and metadata FNV hashes, section page offsets, sender version string, RSDP copy. Per process: 2 pages (record + FPU); shared File objects are deduped into a 64 B/file table and refcounted on restore. Receiver prints the sender/own version and accepted range, drops processes on an unsupported version, keeps pids (fresh pid + ppid remap on collision, next_tid bumped), carries zombies, and resumes parked syscalls via `kx_restart_entry` (callers get 1 via `kx_resume_entry`). Syscall 410 returns the generation (ungated). New `user/bg` reads half of a 96 KiB file, waits for generation 1, reads the rest through the carried fd and checks a 16 KiB heap pattern. Boot test: `bg 1 &`, `hello z &`, `kexec next`, `hello after kexec`, `wait`: 3 processes (pids 52/54/55 kept), 2 files, 46 pages, 264 KiB region; bg matches a fresh read; `wait` reaps 54 and 55 exit 0. Gaps: a pure user-mode spinner that never syscalls makes kexec return EBUSY (no IPI-based preemptive parking); drivers are restarted, not carried; only one format version exists and there is no negative test for an unsupported version.

## Phase 3 — Machine-readable compiler and test tooling
*Pillars: B, C.*
1. `forgec --diagnostics=json` emits file/line/col, a code, a message, and fix-it spans for every error. Test: a golden JSON file for each error class in tests/diag.
   - *Status: done.* `forgec in.forge out.s --diagnostics=json` prints one JSON object per error on stderr (schema v1: `version, severity, code, file, line, col, end_line, end_col, message, fixits[]`; 1-based columns, end exclusive; a fix-it replaces `[col,end_col)` on its line with `replace`, plus a `note`). Both the parser/codegen path (`die`) and the type checker (`tc_err`) route through `diag_emit`; lexer errors record the exact offset, name errors locate the quoted identifier on the line, type errors use the token position. Each source carries its file name (imports report their own file). Codes: E0001–E0003 file/include, E0100 other parse/codegen, E0101 bad character, E0102 unterminated string, E0103 indentation, E0104 newline in f-string, E0201 undefined function, E0202 undefined name, E0203 unknown method, E0300 other type error, E0301 argument type, E0302 assignment, E0303 operand types, E0304 missing argument, E0305 missing return, E0306 return type, E0307 index type, E0308 int literal range, E0309 unknown keyword, E0310 unary operand, E0311/E0312 list/str index, E0313 return value expected, E0314 parameter default, E0315 arity. Fix-its: delete a bad character, close an unterminated string at end of line, re-indent to the enclosing level, and "did you mean" replacements for undefined names/functions/methods (closest user identifier, edit distance ≤2). Text output without the flag is unchanged. Tests: 30 golden files in `tests/diag` (all error classes from tests/errors and tests/typeerrors plus typo, keyword, unary, list-index, EOF-string cases), a schema check of every golden line, and a missing-input check. Gaps: only the first error is reported (the compiler stops at it); type errors other than names have no fix-it yet; columns are byte columns.
2. `forgec --emit=ast-json` produces a stable, versioned AST schema. Test: a round-trip, AST → pretty-printer → AST, is identical for the whole selfhost compiler.
   - *Status: done.* `forgec in.forge out.json --emit=ast-json` writes `{"forge_ast":1,"file":F,"pragmas":[...],"root":NODE}` with `NODE = {"k":KIND,"l":LINE[,"v":VALUE][,"c":[children]]}`; `--emit=pretty` writes canonical source from the same tree. The AST comes from a separate strict recursive-descent parser (`a_*` in compiler.forge) over the raw token stream of one file (no prelude, no include inlining, no std-module renaming); f-strings appear in their desugared `"" + ... + str(x)` form and `# forge:` pragma lines are kept because they change code generation. Node kinds are listed in docs/SYSTEMS.md. Tests (tests/ast, run by run_tests.sh): `roundtrip.sh` — for 107 files (compiler, prelude, tools, every test, every example and kernel .fsi) AST(src) == AST(pretty(src)) ignoring line numbers, and pretty is a fixpoint; `semantic.sh` — all 44 pretty-printed tests/*.forge programs compile and print the same .expected output; `selfpp.sh` — the pretty-printed selfhost compiler builds a compiler whose output on forgec.forge is byte-identical; plus a schema check. Gaps: comments other than pragmas are dropped (fmt in item 4 works at token level for that reason); f-strings are not re-sugared; the pretty-printer keeps parentheses on value tuples and value subscripts (`d[(1, 2)]`) because Forge types them differently from bare tuples.
3. Grammar freeze:
   - an EBNF in docs/GRAMMAR.md;
   - a conformance suite that parses every example;
   - a test that fails if the parser accepts anything outside the grammar (fuzzed with a grammar-based generator).
   - *Status: done.* docs/GRAMMAR.md (version 1) is an EBNF of the whole language — lexical classes, statements, the 15 expression precedence levels, comprehensions, params, targets — with each rule tied to the `a_*` parser function that implements it; the strict AST parser is the reference. Conformance (tests/grammar/run.sh, run by run_tests.sh): `valid/all_productions.forge` uses every production and must parse; 30 `invalid/*.forge` programs (missing colon, dangling operator, unbalanced brackets, decorator without def, try without handler, bare yield argument, `0b` literal, …) must be rejected with an E0100–E0105 diagnostic; every example, kernel .fsi, tool, test and the compiler must parse (item 2 round trip). `tools/grammar_fuzz.py` generates random programs from the grammar (deep expressions, all statement forms, nested blocks): valid ones must parse and round-trip through the pretty-printer to the same AST, and one-line mutations that leave the grammar (unbalanced, dangling, `= =`, bare keyword, header without block, header without `:`) must be rejected cleanly. CI runs seed 1 with 160 programs; seeds 1–5 were run by hand and pass. Findings while freezing: `@=` is not an operator, `0b`/`0o`/`r""` literals do not exist, and EOF errors now report the last line instead of line 0. Gaps: the fuzzer's invalid oracle is mutation-based, not a full grammar complement; the code-generating parser still accepts a few legacy forms beyond the grammar (it is not the one fuzzed).
4. `forge fmt` is a canonical formatter. Test: it is idempotent on all sources, and the repo is kept formatted in CI.
   - *Status: done.* `forge fmt [--check] [files]` (tools/fmt.forge, built to build/fmt on demand; no files = the repo set from tools/fmt_files.sh) is a line/token-level formatter, so comments survive: 4 spaces per block level, continuation lines keep their offset from the opening line, single spaces between tokens, none after openers / before closers, commas and colons, one after a comma, two before an inline comment, no trailing whitespace, at most 2 blank lines, none at file start/end, one final newline; triple-quoted string contents are untouched. The whole repo (110 files, incl. compiler.forge) was formatted; ast-json of every file, line numbers included, was identical before and after, and FIXPOINT holds. tests/fmt/run.sh (in run_tests.sh): golden, idempotence, --check detects, repo is fmt-clean, AST-preserving on a formatted copy. Gaps: no line wrapping or operator-spacing normalisation beyond whitespace collapse; error fixtures (tests/diag, errors, typeerrors, grammar/invalid) are excluded because their goldens are column-sensitive.
5. `forge test` runs inline `test "name":` blocks and gives a JSON report. `forge verify` runs the Phase 4 checkers as a gate.
   - *Status: done.* `test "name":` blocks (grammar v1.1 soft keyword, AST node Test, pretty-printed), `forgec --test` runner, `forge test` (per-test process isolation, 10 s timeout, JSON report) and `forge verify` (parse + fmt + build + test gate, JSON report); see SYSTEMS.md. tests/unit/*.forge hold the first 7 unit tests; tests/testblocks/run.sh (8 checks, in run_tests.sh) covers the JSON schema, failure detection, quoted names, normal builds ignoring tests with line numbers intact, AST/pretty, and verify catching fmt and parse failures. Gaps: no fixtures/setup sharing, no per-test filter or parallelism; a file's top-level code runs before its tests; the header rewrite is line-based, so a column-0 `test "x":` line inside a triple-quoted string would be rewritten; verify has no type-only or effect checker yet (typecheck runs as part of build).

## Phase 4 — Memory-safe Forge by default
*Pillar: A. Closes SYSTEMS.md item 6.*
1. **Slices** `[]T` carry (ptr, len), with bounds checks everywhere. A range-analysis pass elides checks proven safe. Tests:
   - out-of-bounds code traps with a precise diagnostic;
   - the bench suite is ≤ 5% slower with checks on;
   - the elision count is reported.
   - *Status: done (freestanding/kernel backend).* Spelled `slice[T]` instead of `[]T` so frozen grammar v1.1 (a subscript expression) is unchanged. A slice is a 16-byte (ptr, len) value: `slice(p, n)`, `x[a:b]` / `x[:b]` / `x[a:]` on arrays and slices (checked 0 ≤ a ≤ b ≤ len), `len(x)` (constant for arrays), slice parameters passed in two registers, copy-on-assign; returning a slice/struct/array is a compile error for now. Every array and slice index is checked (unsigned compare, so negative indices fail); a failure calls `forge_bounds_fail(line, idx, len, file)` with the *original* file:line (fs_include now keeps an expanded-line map), then `ud2` (bare `ud2` when no handler exists). tests/fs/linux.fsi prints `bounds check failed: f.forge:5: index 3 out of range for length 3` and exits 134; the kernel panics with the same text. Constant out-of-range array indices are compile errors. Elision: `for v in range(len(x))`, `range(C, len(x))`, `range(K)` (literal or named constant K ≤ array length, literal C ≥ 0, positive step) drop the check on `x[v]` when the body never assigns or takes `addr()` of v or x. `--bounds-stats` prints `bounds: S sites, C checked, E elided`; the kernel is 278 sites, 177 checked, 101 elided. `--no-bounds` / `# forge: no-bounds-checks` turn checks off for measurement. tests/bounds/run.sh (13 checks, in run_tests.sh): 3 traps with exact diagnostics, 2 compile-fail cases, bare ud2, the elision count, flag/pragma off, and a sieve/histogram/prefix-sum bench (best of 5) that must be ≤ 5% slower checked; measured ~0–4%. The checks found a real kernel bug: kexec quiesce called `ioapic_mask(i)` for i up to 23, reading past the 16-entry `irq_gsi` table; it now masks IOAPIC pins directly (`ioapic_mask_pin`). Gaps: the hosted (GC runtime) backend already bounds-checks lists and strings at runtime and has no slice type; `ptr[T]` indexing is still unchecked (item 3 makes it `unsafe`); elision is syntactic (no general range analysis across `while` loops).
2. **No null:** `ptr[T]` is non-null, and `?ptr[T]` must be checked before use. Test: compile-fail cases, and the kernel compiles with zero unchecked nullables.
   - *Status: done (freestanding/kernel backend).* Spelled `nptr[T]` instead of `?ptr[T]` (the lexer has no `?`; grammar v1.1 unchanged). `ptr[T]` can no longer hold null: a literal `0` or an `nptr[T]` value converting to `ptr[T]` (assignment, argument, return, field store) is a compile error; a `ptr[T]` local needs an initializer and a `ptr[T]` global a non-null one. Indexing or field access through an `nptr[T]` is an error until it is narrowed. Flow-sensitive narrowing for locals/params: `if x != 0:` / `if x:` / `u64(x) != 0` (also as top-level `and` conjuncts) narrow inside the body; `a and b` / `x == 0 or b` narrow while compiling b; `if x == 0:` / `if not x:` whose block ends in return/break/continue/panic (no elif/else) narrows x for the rest of the block; a store of a proven non-null value narrows, any other store clears; leaving a block keeps only facts true on entry and still true; entering a `while`/`for` drops facts for locals the loop assigns. Globals are never narrowed (copy to a local first). Kernel: nullable returns are now `nptr` (`mod_load`, `mod_fail`, `proc_find_l`, `fd_get`, `proc_spawn[_args]`, `blkd_start`, `blkd_spawn`, `kx_restore`, globals `mod_err`/`mod_err_sym`); every caller checks, and self-tests use panicking `proc_spawn_ok` / `mod_load_ok`. This found a real unchecked case: module_test reloaded hello.ko and dereferenced the result without checking it. The EFI loader's `con`/`bs` globals are `nptr` behind `con_out()` / `bsfn()`. The kernel, loader, user programs and modules all compile with zero unchecked nullables. Compile errors now report the original file:line through `include`. tests/nonnull/run.sh (14 checks, in run_tests.sh): a runtime program (linked list walk, and/or/early-exit narrowing) and 13 compile-fail cases. Gaps: explicit int→pointer casts (`ptr[T](0)`) still bypass the check (item 3 confines them to `unsafe:`); zero-initialised structs/arrays with `ptr[T]` fields are not checked; `addr()` of an nptr local does not invalidate its narrowing; narrowing does not follow `while x == 0:` exits or `elif` chains.
3. **`unsafe:` blocks:** raw `vload/vstore`, int→pointer casts, inline asm, and MMIO are allowed only inside them. A `forge verify --unsafe-report` lists every block. Test: the counts are tracked in CI, and the kernel's unsafe surface shrinks over time.
   - *Status: done (freestanding/kernel backend).* Spelled `with unsafe:` (parses as a frozen-grammar v1.1 `with` statement) plus a function decorator `@unsafe`; `naked` functions are implicitly unsafe. Outside an unsafe region these are compile errors (`X is unsafe: put it in a `with unsafe:` block or mark the function @unsafe`): `asm`, `load*/store*/vload*/vstore*`, port `in*/out*`, `call_ptr`, `call_efi`, `memcpy`/`memset`, `lgdt/lidt/ltr/invlpg/wrmsr/rdmsr/cli/sti/hlt/wbinvd`, all raw-address `atomic_*`, explicit `ptr[T](int)` / `nptr[T](int)` casts, implicit int→pointer conversion (literal 0 into `nptr` stays safe), `nptr`→`ptr` casts, pointer casts that change the element type, and `ptr[T]` indexing other than `p[0]` (use a slice). This closes the 4.2 gap: `ptr[T](0)` is now always an error, even in unsafe code (4 kernel `return ptr[X](0)` sites became `return 0` from nptr functions; module.fsi's `err` became `nptr[u8]`). `forgec --unsafe-report` lists every region (`unsafe: FILE:LINE fn|naked fn|block in F ops=N`, top-level asm) and a summary; `--unsafe-fix` lists the functions that need `@unsafe` (used once to migrate 213 functions mechanically); `tools/forge_verify.sh --unsafe-report` adds an `unsafe` check with the summary. Current surface: kernel 178 of 327 functions, 758 ops, 7 top-level asm blocks; EFI loader 12 functions/82 ops; user programs 6–8 functions each (the linux syscall shims); modules 0–3. tests/unsafe/run.sh (29 checks, in run_tests.sh): a runtime program using a block and an @unsafe function, 10 compile-fail cases (including `ptr[T](0)` inside @unsafe), and `baseline.txt`, which fails CI if any program's function/block/op/asm count grows. Gaps: unsafety is mostly function-granular after the mechanical migration (shrinking it to blocks is follow-up work); hosted (GC) code has no unsafe operations to gate; struct-pointer field access is not considered unsafe (the pointer is already non-null and typed).
4. **Ownership and borrowing** (affine `own T`, `&T` and `&mut T` scoped borrows, regions for arenas and kernel per-request memory). Tests: compile-fail tests for use-after-free, double free, and aliasing a `&mut`. The user programs and shell compile in safe mode.
   - *Status: done (freestanding/kernel backend).* Spelled `own[T]`, `ref[T]`, `mut[T]` (frozen grammar v1.1 has no `&`); all three are non-null pointers. `own[T]` is affine: a whole-value use (assignment, argument, return) moves it, and any later use is `use of moved value `b` (moved at FILE:LINE)`, which covers use-after-free (`free(b)` then `b.v`) and double free; moving or assigning while borrowed, and overwriting a still-live own (it would leak), are errors. `borrow(x)` gives a `ref[T]`, `borrow_mut(x)` a `mut[T]` of an own local x. Inside call arguments the borrow lasts for the call; at statement level it can only initialize a new local and lasts until the end of the block that declares it (lexical, not NLL). Rules: many `ref` or one `mut`; while a `mut` is live the owner is unusable, so `f(m, borrow(m))` is rejected (aliasing a mut); stores through a `ref` are errors; a `mut[T]` cannot be copied; copying a `ref` keeps the owner borrowed; `mut`→`ref` converts implicitly; raw `ptr`↔own/ref/mut conversions and casts are unsafe ops; own→ref/mut without borrow() is an error. Moves are flow-sensitive: `if`/`elif`/`else` join the moved states of branches that fall through; a loop that moves an outer own value (at the end of the body or a `continue`) is an error. Restrictions: no own/ref/mut struct fields or globals, no ref/mut returns (no lifetimes). `slice(p, n)` over a raw pointer is now an unsafe op. Safe mode: `# forge: safe` makes any `@unsafe` function, `with unsafe:` block or top-level asm in the main file an error (included libraries are the trusted base). sh, bg, forktest, hello, cat, sum and crash are safe-mode programs; raw memory goes through four trusted `ulib.fsi` helpers (`mem_get8/set8/get64/set64`), sh parses dirents with array indexing. Only blkd (a driver) and fault (deliberate fault) keep unsafe code. tests/own/run.sh (19 checks, in run_tests.sh): a runtime program and 18 compile-fail cases (use after move, use after free, double free, aliasing a mut, borrow while mut-borrowed, mut while shared, store through ref, move while borrowed, move in loop, move in one branch, leaking reassign, dead borrow, borrow into an existing variable, mut copy, own as ref, raw→own, borrow return, safe mode). Gaps: affine not linear (dropping an own without freeing is not detected); no own fields, so kernel data structures are not yet ownership-typed; regions/arenas not done; `addr()` of an own local escapes the checks; borrows are lexical.
5. **Generics** (monomorphized) and `defer`. Stdlib containers become generic: `Vec[T]`, `Map[K,V]`.
   - *Status (defer, 4.5a): done (freestanding).* Spelled `with defer:` (a frozen-grammar v1.1 `with` statement). The block must be at the top level of a function body; it is registered when reached and re-emitted, newest first, before every later `return` (after the return value is computed; %rax is preserved) and at a fall-through function end. It cannot contain `return`, `break`/`continue` or another defer. Block-scoped borrows end before the defers run; ownership is checked on each emitted path, so `with defer: free(b)` followed by an explicit `free(b)` is a use of a moved value. `panic` does not run defers. tests/defer/run.sh (5 checks): LIFO order across early return / break / fall-through and 4 compile-fail cases.
   - *Status (generics, 4.5b): done (freestanding).* `@generic(T, ...)` decorates a `def` or `struct` (frozen grammar: decorator + `Name[T]` subscript types). Monomorphized on demand: each distinct type tuple gets one instance (struct type `Pair[u64]`; function symbol `name__g<N>`), type-checked with the parameters bound to concrete types, so all ownership/bounds/unsafe rules apply per instance. Calls are `f[T](...)` or inferred `f(...)` (unification over ptr/nptr/slice/own/ref/mut and generic struct arguments; literal-only params default to i64; otherwise "cannot infer type parameter"). `T(x)` casts and `sizeof(T)` work on bound params. No trait bounds: an instance that misuses T fails when instantiated. Generic functions cannot have their address taken. tests/generic/run.sh (5 checks).
   - *Status (Vec/Map, 4.5c): done (freestanding stdlib).* std/vec.fsi (`Vec[T]`: vec_init/reserve/push/get/set/pop/len/free) and std/map.fsi (`Map[K, V]`, open addressing + tombstones, integer-like keys: map_init/put/get/has/del/len/free) are generic, trusted `@unsafe` library code over an includer-provided `forge_alloc(bytes) -> u64` / `forge_free(p, bytes)`; callers stay in safe code (`vec_push(addr(v), x)`). vec_get/vec_set index through `slice(data, len)`, so out-of-range access traps via forge_bounds_fail. Not yet used by the kernel (it has no general-purpose heap API wired to forge_alloc); keys are compared with `==` (no user hash/eq). tests/generic: std.forge (Vec[u64], Vec[u8], Map[u64,u32] with growth/delete, alloc/free balance) and oob.forge (trap).
6. **Weaker atomics orderings** (acquire/release).
   - *Status (4.6): done (freestanding/kernel backend).* Typed, safe atomics with an explicit ordering word: `atomic_load(p, o)`, `atomic_store(p, v, o)`, `atomic_swap(p, v, o)`, `atomic_fetch_add(p, v, o)`, `atomic_cas(p, expected, new, o)` (returns the old value) and `atomic_fence(o)`, where `p` is a non-null `ptr[T]`/`own`/`mut` (loads also accept `ref[T]`) to an integer of 1/2/4/8 bytes and `o` is `relaxed|acquire|release|acq_rel|seq_cst`. Invalid combinations are compile errors (release/acq_rel loads, acquire/acq_rel stores, relaxed fence). x86-64 TSO lowering: loads and relaxed/release stores are plain `mov`, seq_cst stores `xchg`, RMW ops `lock`-prefixed, `atomic_fence(seq_cst)` = `mfence` (other fences are compiler-only; the backend does not reorder memory accesses). Usable from `# forge: safe` code; the raw-address `atomic_*32/64` intrinsics remain and stay unsafe. tests/atomic/run.sh (8 checks: safe-mode publish/consume + RMW semantics, codegen mapping, 6 compile-fail cases). Gap: the kernel still uses the raw intrinsics (migration to typed atomics is follow-up); only x86-64 is targeted, so weaker orderings do not yet produce cheaper code than seq_cst except for stores.
   - *Status (post-Phase-4 cleanup): done.* All 66 raw-address `atomic_*64` sites in the kernel became typed atomics (`atomic_fetch_add(addr(x), 1, acq_rel)`, `atomic_load(..., acquire)`, `atomic_store(..., seq_cst)`; identical x86 code), and `spin_lock`/`spin_unlock` take `ptr[u64]` and are safe (swap-acquire / store-release; 168 call sites rewritten). `@unsafe` was then stripped from every kernel function and re-applied only where `--unsafe-fix` reports an unsafe op. Kernel unsafe surface: 178 functions / 758 ops -> 163 / 692 for the kernel's own code; 171 / 734 including the 8 trusted std/vec+map instances now compiled in (baseline.txt updated to 171 0 734 7). The kernel provides `forge_alloc`/`forge_free` over kmalloc/kfree and `vecmap_test` (boot log: `generic Vec/Map OK`, heap leaked 0) exercises `Vec[u64]` past a page and `Map[u64, u64]` with deletes.

## Phase 5 — Capability OS and sandboxing
*Pillars: A, D.*
1. **Handles replace ambient authority.** Every fd/proc/memory object is a capability with rights bits. Syscalls check rights, `dup` can only narrow them, and capabilities pass over IPC channels. Test: a child given a read-only handle cannot write; no global path lookup is possible without a directory capability.
   - *Status: done for file handles (console, files, directories).* Each fd carries rights (READ, WRITE, LOOKUP, DUP, XFER). read/getdents need READ and write needs WRITE. `dup(fd, rights)` (420) needs DUP and fails with EPERM unless the new rights are a subset. `openat(dirfd, path)` (421) needs LOOKUP and rejects absolute paths and `.`/`..`. `rights(fd)` is 422. open, stat and exec resolve only through the root-directory capability at fd 3; without it they return EACCES and the kernel logs `cap: pid N denied ...`. Rights survive fork and kexec, packed into the high half of the handoff fd slot. Test: `captest`, run by the boot shell script. Process and memory handles, and passing capabilities over IPC, come in 5.2.
2. **IPC channels** carry messages plus handles, with wait queues. Test: ping-pong latency is measured, and a handle is transferred.
   - *Status: done.* `chan(fds)` (423) creates two endpoint handles. `send(fd, buf, n, h)` (424) needs WRITE on the endpoint and XFER on h. `recv(fd, buf, n, &h)` (425) needs READ. A message holds 1–64 bytes plus an optional handle. The handle is moved, so the sender loses it and the receiver gets it in a free fd with the same rights. Each direction is a 16-slot ring; receivers and senders block on wait queues. recv returns 0 (EOF) once the peer's end is closed and the ring is empty. Channels come from a static 16-entry table, so none of the code needs `unsafe` beyond what the kernel already had. kexec refuses to run while any channel is open. Test: `chantest` does 2000 ping-pong round trips (about 9 ticks at 100 Hz under QEMU TCG, roughly 45 µs per round trip), refuses a handle without XFER, moves a file handle that the child reads but cannot write and echoes, and checks EOF after the child exits.
3. **Per-app sandboxes:** a manifest declares the capabilities an app gets (dirs, devices, network). The shell launches apps through the manifest. Test: an app that reaches outside its manifest is denied and logged.
   - *Status: done (files and dirs; no device or network grants yet, since there are no such handle types).* `sh: run APP [args]` reads `\EFI\Forge\apps\APP.mf`. Each `read PATH` line becomes a READ|DUP handle and each `dir PATH` line a READ|LOOKUP|DUP handle, on fds 4.. in manifest order; rights are narrowed in place with `restrict` (427). The shell then calls `exec_sandboxed` (426), which drops the root capability (fd 3) and marks the process sandboxed; its forked children inherit that. Each open, stat or exec outside the manifest returns EACCES and the kernel logs `sandbox: pid N (APP) denied OP PATH: not in its manifest`. kexec refuses while a sandboxed process is alive. Test: `run sbtest` reads its granted file (write and widening denied) and looks up inside its granted dir (`..` denied); open, stat and exec outside the manifest are denied and logged.
4. **Kernel hardening:** KASLR, stack canaries, guard pages per thread, and W^X for user ELF (already enforced for the kernel).
