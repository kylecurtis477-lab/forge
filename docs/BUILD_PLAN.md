# Forge build plan

This is the plan to execute, in phase order. It merges the open items from docs/SYSTEMS.md (roadmap items 1–9), the compiler performance list, and six pillars:

- **A. Provable safety.** Forge is memory-safe by default:
  - ownership/borrow or region checking;
  - bounds checks, with elision where they can be proven unnecessary;
  - no null;
  - `unsafe` blocks that are checked.

  The OS uses capabilities, and everything runs sandboxed.
- **B. AI-native.**
  - A tiny, regular grammar.
  - Machine-readable diagnostics and a JSON AST.
  - Built-in test/verify tooling.
  - Later, an OS intent/command layer.
- **C. One language everywhere.**
  - Forge for the kernel, apps, and servers.
  - Generics, slices, a package manager, a stdlib, an LSP, a formatter, and DWARF.
  - Later, ARM64 and GPU backends.
- **D. Instant and seamless.**
  - Fast boot.
  - Reproducible, declarative system configuration.
  - A sandbox per app.
- **E. Auto-parallelism.** SIMD, parallel-for, and a multicore runtime.
- **F. Compatibility.**
  - A Linux syscall ABI layer that runs static Linux ELF binaries.
  - C and Python FFI.
  - Real hardware drivers: NVMe, AHCI, USB/xHCI, e1000/virtio-net, GOP.
  - Our own assembler and linker.

**Invariants for every phase:**

- `./build.sh` prints FIXPOINT OK.
- `./run_tests.sh` and `FORGEC_FLAGS=-O0 ./run_tests.sh` both report 0 FAIL. This includes the QEMU boot tests (kernel-wx, kernel-bios, kernel-uefi, efi-loader-gpt).
- Dual-boot rules hold:
  - install only into `\EFI\Forge\`;
  - GPT only, never taking over a whole disk;
  - the kernel only reads the disk until Phase 8 adds a separate Forge data partition, created only with explicit opt-in.
- Each deliverable is committed as soon as its test passes.

A phase is done when every listed test passes in CI (`run_tests.sh`) on both -O2 and -O0.

## Phase 2 — Never reboot: self-healing, live-updatable system (signature feature 1)
*This phase needs Phase 1's processes, services, and wait queues. Each sub-step is finished and tested before the next one starts.*
1. **Kernel module ABI.** Relocatable Forge modules (ELF ET_REL) are loaded and unloaded at runtime. They get a versioned symbol table and an explicit `init/exit/save_state/restore_state` contract. Test: load, call, and unload a module 1000 times with no leaks.
   - **Status: done.** `examples/kernel/module.fsi`; test modules in `examples/modules/` (forgec + `as` → `.ko`, shipped in `\EFI\Forge\mod\`). KABI 1.0: exports carry a since-minor; wrong major, newer minor, imports newer than the module's ABI, unresolved symbols and truncated images are rejected. Relocations R_X86_64_64/PC32/PLT32/32S with range checks; sections mapped W^X in 1 MiB slots at `0xFFFFFFFFD0000000`. Boot test: 1000 load/call/unload cycles, 0 frames and 0 heap bytes leaked, save/restore state across reload, 4 bad modules rejected.
2. **Drivers as isolated services.** Each driver (virtio-blk, tty/keyboard, later the network) runs as a user-mode or isolated service process. It reaches its device only through granted MMIO/IRQ/DMA capabilities and talks to clients over IPC. Test: injecting a crash into the driver service leaves clients alive.
   - **Status: done (virtio-blk).** `examples/kernel/drv.fsi` + `examples/user/blkd.forge`. The ring-3 `blkd` gets capability syscalls 400–407: port I/O checked against the device's 64-byte I/O window, MSI-X interrupt wait, one contiguous DMA region mapped into it, recv/reply IPC. `vb_read` (so FAT and all file I/O) is routed to it after a handover under `vb_m`. On driver death the kernel resets the device before the DMA frames are freed and fails the in-flight request with EIO. Boot test: init.elf read through blkd is byte-identical; a non-driver caller gets EPERM; an injected NULL write with a request in flight on the device kills blkd (#PF, exit 0x10e), the client gets EIO and continues, the kernel driver takes the device back, 0 frames / 0 heap bytes leaked. Gaps: no IOMMU (DMA not confined), one request in flight, tty/keyboard still in-kernel.
   - *No-restart gap 1 closed (tty/keyboard as a supervised, hot-swappable ring-3 service).* `examples/kernel/kbd.fsi` + `examples/user/kbdd.forge` / `kbdd2.forge`. During the shell session the PS/2 and COM1 IRQ handlers only append raw bytes to a 256-entry kernel journal (`kind<<8|byte`); decoding (scan-code set 1, shift, E0, CR→LF) runs in the ring-3 driver `kbdd` (DRV_KBD, caps(drv), no root fd). Syscalls 411 recv (block for a batch of ≤32 entries; 0 = quiesce), 412 commit (end seq, decoded chars, decoder state word, applied to the tty under rq_lock in one step) and 413 get-state are CAPB_DRV and only for the registered pid. Uncommitted entries stay in the journal, so a dead driver's batch is replayed by its successor, which starts from the last committed state. Two different implementations share the state format (v1: one shift bit, shifted table; v2: left/right shift bits 0 and 2, arithmetic upper case); a swapper asks the running one to quiesce every 10 ticks and the supervisor starts the other. A crash (exit ≠ 0) is restarted the same way, at most 5 times, after which the kernel decodes again. `crash k N` (syscall 408 b=1, still ktest_hooks-gated) makes the batch holding the N-th next entry carry a fault flag; the driver then dies on a bounds trap (#UD). At session end the service is stopped and the kernel decodes any leftover entries with the same state. Boot test: `crash k 4` then `hello Swap OK` typed over the PS/2 keyboard while swaps run: kbdd v1 dies, "restart 1, replaying from entry …", the line arrives intact (`hello: args = 'Swap OK'`), ~36–60 hot swaps, entries in == committed + kernel-drained, dropped 0, lost 0. Also fixed: driver spawns marked the driver kind in a global, so an ordinary process spawned concurrently on another CPU could come up as a driver without a root fd; the kind is now per spawning thread (`Thread.spawn_drv`), and `proc_reap_orphans` leaves driver processes to their supervisor. Gaps: the echo path and line discipline stay in the kernel (the modules of item 4); the journal holds 256 entries (overflow is counted as dropped and fails the test).
   - *No-restart gap 2 closed (NVMe as a supervised, hot-swappable ring-3 service).* `examples/kernel/nvsvc.fsi` + `examples/user/nvmed.forge` / `nvmed2.forge`. `nvme.fsi` splits commands into `nv_submit`/`nv_reap`; when the service is on, `nvme_read/write/flush` go through `nv_io` → `nvs_call`, which hands the request to the ring-3 driver `nvmed` (DRV_NVME, caps(drv), no root fd). Syscalls 414 recv (0 = quiesce), 415 submit (opcode/LBA/count checked exactly against the pending request, writes only inside the Forge partition; anything else refused and counted), 416 reap, 417 reply (seq, status, state word with magic in bits 63:32 and served count), 418 get-state; all CAPB_DRV and registered-pid only. A dying driver's in-flight CQE is drained by the kernel and its request is replayed to the successor. A swapper alternates v1/v2 every 7 requests; ffs_test arms a crash on request 30. Boot test (both forgefs boots): restart 1, replayed ≥1, drained ≥1, ≥3 swaps, forged SQEs refused (v2 probes one at start), served count carried == requests. Also: a driver with an all-bss RW segment had p_offset past the file end and was refused by elf_load; the drivers carry one initialized word. Gaps: admin queue, interrupts and the queue memory stay in the kernel.
   - *No-restart gap 3 closed (more than one live-patch site).* `livepatch.fsi` keeps a table of up to 8 registered `@patchable` sites, each with its own text hash and patched flag (`lp_find`, `lp_site_hash`, `lp_npatched`; registering twice is a no-op, a 9th site gets LP_EFULL, applying to an unregistered address is refused). Second site: `sys_getppid` (syscall 110), now `@patchable` over the unpatchable helper `kcur_ppid` (exported to modules). `getpid2.ko` carries replacements for both plus a wrong variant of each; its counters moved to shared helpers, so its unsafe counts went down (3 0 4 0). Boot test: hammers on 3 CPUs call both syscalls; 25 rounds patch both sites, check both are live, then revert them one at a time in alternating order, checking after each revert that the other site is still patched; both wrong replacements are rejected (rejects 2); both hashes restored and neither patch reached after revert; 0 wrong results, 0 leaks. Gaps: the quiescence check is still the hammers' counters rather than a stack walk; multi-site patches are applied one site at a time (no single stop-machine transaction across sites).
   - *No-restart gap 4 closed (driver state carried across the kexec handoff).* The kexec session now runs with the supervised input service (kbdd) on. With every other CPU halted and input interrupts off, `kxd_save` writes a driver-state section into the handoff header page past KXH_BYTES (own magic and hash, so the v3 format and its adoption rules are unchanged): driver kind and version, the decoder state word, the journal entries not yet committed and the service counters. The new kernel's `kxd_adopt` validates it before the region is freed, and `kbd_service_start_from(1)` starts the same driver version on the carried journal and state instead of a fresh service. Boot test (BIOS and both UEFI boots): a shift press + release is queued at handoff time where no driver in the old kernel can take it; the generation-1 driver replays the 2 carried entries (entries committed ≥ carried + 2), commits keep counting from the carried total, restart/swap counters carry over, dropped 0, then the shell types `hello after kexec` through it. Gaps: only the input service has a record (the NVMe and block services are not running across the test's handoff and still start fresh); driver processes themselves are restarted, not carried.
   - *True self-hosting, step 1 (seed replaces the Rust bootstrap).* `seed/forgec-seed` is a checked-in forgec binary (the fixpoint compiler, built by fas/fld), pinned by `seed/forgec-seed.sha256`, which build.sh checks before using it. build.sh no longer runs `cargo`: the seed compiles tools/embed.forge and selfhost/forgec.forge (stage2); stage2 → stage3 → stage4 must still be byte-identical, and build.sh reports `SEED OK` when the rebuilt compiler is byte-identical to the seed (`SEED NOTE` after a compiler change, until `tools/reseed.sh` refreshes it). The Rust bootstrap is an optional cross-check: `FORGE_RUST_CHECK=1 ./build.sh` builds src/main.rs and checks that its stage1 emits the same stage2.s. Verified with `target/` removed. Step 2 done (below).
   - *True self-hosting, step 2 (no binutils in the build).* `seed/fas-seed` and `seed/fld-seed` (pinned with forgec-seed in `seed/seed.sha256`) assemble and link embed, stage2 and the stage2-built fas/fld; every later stage uses the freshly built fas/fld. build.sh reports `SEED TOOLS OK` when the rebuilt fas/fld are byte-identical to the seeds. Verified with `as`, `ld`, `cargo` and `rustc` blocked on PATH: FIXPOINT OK from the seed. GNU as/ld remain only as reference oracles in tests/fas and tests/fld.
3. **Supervisor with automatic restart.** Death is detected, the service restarts with its saved state, and in-flight requests are replayed idempotently. Test: the boot test kills the block driver in the middle of `cat`, and the output is still byte-identical; the restart count is reported.
   - *Status: done.* For the whole shell session `blkd` runs under a supervisor kernel thread (`drv.fsi`). The boot script runs `crash 40` (syscall 408, a fault-injection hook) and then `sum` on the 96 KiB `\EFI\Forge\docs\big.bin`. blkd dies with a request in flight. The supervisor reaps it, respawns it from the cached image with its restart generation as an argument, and the kernel-held request journal replays the read. Replies are matched by sequence number, so a stale reply cannot complete a newer request. The FNV-1a hash of the file matches the one computed on the host, and the test reports "blkd restarts 1 … replayed 1". After 5 restarts the supervisor gives up and fails requests with EIO. The session leaks 0 frames and 0 heap. Gaps: the test file is read with `sum` (which hashes it) rather than `cat`, so the comparison is by hash; the device is the only driver state, and it is rebuilt on restart (there is no state blob to save); there is one request slot; writes are not replayed, since only reads exist.
4. **Hot-swap with state transfer.** Replace a running driver or module with v2. The old version quiesces, serialises its typed state, the new version restores it, and clients see only latency. Test: swap the tty driver while the shell is reading, and no keystroke is lost.
   - *Status: done.* The tty line discipline goes through three function pointers: push, lines and pop. v0 is built into the kernel, and `tty1.ko` (a 512-byte head+count ring) and `tty2.ko` (a 1 KiB ring with free-running indices, which recounts lines on restore) are interchangeable modules that share one state format. During the shell session a swapper thread cycles v1↔v2 every 2 ticks, and at the end it swaps back to v0. Each swap loads the new module, then, under rq_lock, saves the old state, restores it into the new module and switches the pointers. All tty calls run under rq_lock, so no CPU can still be in the old code when it is unloaded. If a restore fails, the swap is aborted. Boot test: about 120 swaps, about 40 of them with a partial line queued; pushed == consumed + erased, lost 0, dropped 0; no leaks. Gaps: the swap is triggered by a timer rather than by an operator command; the echo path is not part of the module. The fault-injection syscall 408 now returns EPERM unless the kernel's boot self-test has armed it for its shell session, and drv_test checks this.
5. **Live kernel patching.** Function-level patches are applied with stop-machine via IPIs. Each patched function gets a jump at its entry, verified by its hash. Rollback is supported. Test: patch `sys_getpid` while 4 CPUs hammer it; results switch atomically and rollback restores them.
   - *Status: done.* forgec (both `selfhost/forgec.forge` and the embedded `compiler.forge`) has a new `@patchable` decorator that emits a 5-byte nop (`0f 1f 44 00 00`) at the 16-byte-aligned function entry. `sys_getpid` is `@patchable`. `livepatch.fsi` registers the target, recording an FNV hash of its first 32 bytes. To apply a patch it checks the nop and the hash, then writes `jmp rel32` to the replacement in `getpid2.ko`. The write is a single aligned 8-byte store through the HHDM alias, so kernel text stays read-only. It happens under stop-machine: the other 3 CPUs are parked with interrupts off in the shootdown IPI and serialise with cpuid before continuing. Revert writes the nop back and re-checks the hash. `lp_apply_checked` tests the replacement before installing it (the wrong `lp_getpid_bad` is rejected and never becomes reachable), then tests the live entry point and rolls back if that fails. Boot test: 3 hammer threads on 4 CPUs make about 2.5 M calls while the patch is applied and reverted 25 times (about 1.5–1.9 M of the calls go through the patch); 0 wrong results; 1 rejection and 1 rollback; hash restored; patched code is not reached after rollback; 0 leaks; 6 back-to-back OS test runs passed after a stop-machine round-generation fix (a CPU that missed the release could get stuck into the next round). Gaps: only one patch site is tracked (closed by no-restart gap 3); the module is unloaded after a quiescence check based on the known callers (the hammers' loop counters plus an in-patch active counter), not a general stack walk; user processes call getpid through the same entry, but the test does not run them concurrently with the patching.
6. **kexec-style handoff (fallback).** Boot a new kernel image while keeping user state: process memory, fds, and the console are serialised into a handoff region the new kernel adopts. Dual-boot rules still apply, and nothing is written to disk. Test: the shell survives a full kernel replacement and the next command works.
   - *Status: done.* Syscall 409 (`kexec`, only when `ktest_hooks` is set, like 408) is in `kernel/kexec.fsi`. It pins the caller to the BSP (CPU 0) and sleeps until it runs there, so the successor's INIT-SIPI never hits a parked old BSP. It reads `\EFI\Forge\kernel.elf` from the read-only ESP, verifies it, and copies its PT_LOADs to a 2 MiB-aligned free physical range. It then builds a handoff region in free frames. The region holds: a header (magic, generation, brk, pid, FNV hash), a fresh BootInfo (`BOOT_KEXEC`, memory map with the region marked `MEM_HANDOFF`, saved RSDP copy), loader-style page tables, an identity-mapped jump stub, the FPU state, the syscall frame, args, and an index of every present 4K user page plus its data. To quiesce, it switches off input, resets virtio, masks the IOAPIC and LAPIC timer, and parks APs under stop-machine with `tlb_halt`, then jumps. The new kernel boots normally (its own ACPI/SMP/drivers), sees `bi.handoff`, checks the hash, rebuilds the process (pages, brk, args, console fds 0–2, FPU), and resumes it in a fork-style thread that returns 1 from the syscall. It then frees the region. Boot test (`boot.py`: `hello x`, `kexec`, `hello after kexec`, `exit`): the shell keeps its command counter across the swap (pid 52 → 34, 21 pages, 140 KiB region), runs the next command, and exits 0. `os/kexec-no-disk-write` checks the sha256 of the GPT disk image is unchanged after the efi-loader-gpt boot. All three boot paths pass, 3 back-to-back runs. Gaps: only the calling process survives (others, kernel threads, modules, and driver state are not carried over; drivers re-probe); only console fds survive; ACPI reclaim memory is no longer reclaimed so the successor can reparse tables; same kernel image (no version negotiation of the handoff format beyond the magic).
   - *Hardening (format v2):* `kexec next` (409 with arg 1) loads `\EFI\Forge\kernel-next.elf`, a genuinely different build (kernel/build.sh rewrites the version string to `forge-kernel 0.2.6-next` and fails if the ELFs are identical). The sender freezes every non-driver user process at a syscall boundary (syscall_dispatch entry, or inside the sys_wait / tty_read block loops; per-thread `sc[5]` records nr+args since the 80-byte frame lacks them), waiting up to 300 ticks, else prints "handoff abandoned" and returns EBUSY. Header v2 (448 B): magic, version, min/max accepted, sizes, counts, separate data and metadata FNV hashes, section page offsets, sender version string, RSDP copy. Per process: 2 pages (record + FPU); shared File objects are deduped into a 64 B/file table and refcounted on restore. Receiver prints the sender/own version and accepted range, drops processes on an unsupported version, keeps pids (fresh pid + ppid remap on collision, next_tid bumped), carries zombies, and resumes parked syscalls via `kx_restart_entry` (callers get 1 via `kx_resume_entry`). Syscall 410 returns the generation (ungated). New `user/bg` reads half of a 96 KiB file, waits for generation 1, reads the rest through the carried fd and checks a 16 KiB heap pattern. Boot test: `bg 1 &`, `hello z &`, `kexec next`, `hello after kexec`, `wait`: 3 processes (pids 52/54/55 kept), 2 files, 46 pages, 264 KiB region; bg matches a fresh read; `wait` reaps 54 and 55 exit 0. Gaps: a pure user-mode spinner that never syscalls makes kexec return EBUSY (no IPI-based preemptive parking); drivers are restarted, not carried; only one format version exists and there is no negative test for an unsupported version.
   - *Format v4 (Phase 11.1a):* the process record carries the 128-byte syscall frame (argument registers saved, as the Linux ABI needs) and the process ABI (word +56, bit 40); a v4 kernel adopts only v4.
   - *Format v5 (v1.3 item 7):* each process record is a process-state v1 record (pstate.fsi) with its own header word; the receiver refuses a record whose header it does not support.

## Phase 3 — Machine-readable compiler and test tooling
*Pillars: B, C.*
1. `forgec --diagnostics=json` emits file/line/col, a code, a message, and fix-it spans for every error. Test: a golden JSON file for each error class in tests/diag.
   - *Status: done.* `forgec in.forge out.s --diagnostics=json` prints one JSON object per error on stderr (schema v1: `version, severity, code, file, line, col, end_line, end_col, message, fixits[]`; 1-based columns, end exclusive; a fix-it replaces `[col,end_col)` on its line with `replace`, plus a `note`). Both the parser/codegen path (`die`) and the type checker (`tc_err`) route through `diag_emit`; lexer errors record the exact offset, name errors locate the quoted identifier on the line, type errors use the token position. Each source carries its file name (imports report their own file). Codes: E0001–E0003 file/include, E0100 other parse/codegen, E0101 bad character, E0102 unterminated string, E0103 indentation, E0104 newline in f-string, E0105 expected (parse), E0106 reserved effect annotation (v1.2), E0201 undefined function, E0202 undefined name, E0203 unknown method, E0300 other type error, E0301 argument type, E0302 assignment, E0303 operand types, E0304 missing argument, E0305 missing return, E0306 return type, E0307 index type, E0308 int literal range, E0309 unknown keyword, E0310 unary operand, E0311/E0312 list/str index, E0313 return value expected, E0314 parameter default, E0315 arity. Fix-its: delete a bad character, close an unterminated string at end of line, re-indent to the enclosing level, and "did you mean" replacements for undefined names/functions/methods (closest user identifier, edit distance ≤2). Text output without the flag is unchanged. Tests: 30 golden files in `tests/diag` (all error classes from tests/errors and tests/typeerrors plus typo, keyword, unary, list-index, EOF-string cases), a schema check of every golden line, and a missing-input check. Gaps: only the first error is reported (the compiler stops at it); type errors other than names have no fix-it yet; columns are byte columns.
2. `forgec --emit=ast-json` produces a stable, versioned AST schema. Test: a round-trip, AST → pretty-printer → AST, is identical for the whole selfhost compiler.
   - *Status: done.* `forgec in.forge out.json --emit=ast-json` writes `{"forge_ast":1,"file":F,"pragmas":[...],"root":NODE}` with `NODE = {"k":KIND,"l":LINE[,"v":VALUE][,"c":[children]]}`; `--emit=pretty` writes canonical source from the same tree. The AST comes from a separate strict recursive-descent parser (`a_*` in compiler.forge) over the raw token stream of one file (no prelude, no include inlining, no std-module renaming); f-strings appear in their desugared `"" + ... + str(x)` form and `# forge:` pragma lines are kept because they change code generation. Node kinds are listed in docs/SYSTEMS.md. Tests (tests/ast, run by run_tests.sh): `roundtrip.sh` — for 107 files (compiler, prelude, tools, every test, every example and kernel .fsi) AST(src) == AST(pretty(src)) ignoring line numbers, and pretty is a fixpoint; `semantic.sh` — all 44 pretty-printed tests/*.forge programs compile and print the same .expected output; `selfpp.sh` — the pretty-printed selfhost compiler builds a compiler whose output on forgec.forge is byte-identical; plus a schema check. Gaps: comments other than pragmas are dropped (fmt in item 4 works at token level for that reason); f-strings are not re-sugared; the pretty-printer keeps parentheses on value tuples and value subscripts (`d[(1, 2)]`) because Forge types them differently from bare tuples.
3. Grammar freeze:
   - an EBNF in docs/GRAMMAR.md;
   - a conformance suite that parses every example;
   - a test that fails if the parser accepts anything outside the grammar (fuzzed with a grammar-based generator).
   - *Status: done.* docs/GRAMMAR.md (version 1) is an EBNF of the whole language — lexical classes, statements, the 15 expression precedence levels, comprehensions, params, targets — with each rule tied to the `a_*` parser function that implements it; the strict AST parser is the reference. Conformance (tests/grammar/run.sh, run by run_tests.sh): `valid/all_productions.forge` uses every production and must parse; 30 `invalid/*.forge` programs (missing colon, dangling operator, unbalanced brackets, decorator without def, try without handler, bare yield argument, `0b` literal, …) must be rejected with an E0100–E0105 diagnostic; every example, kernel .fsi, tool, test and the compiler must parse (item 2 round trip). `tools/grammar_fuzz.py` generates random programs from the grammar (deep expressions, all statement forms, nested blocks): valid ones must parse and round-trip through the pretty-printer to the same AST, and one-line mutations that leave the grammar (unbalanced, dangling, `= =`, bare keyword, header without block, header without `:`) must be rejected cleanly. CI runs seed 1 with 160 programs; seeds 1–5 were run by hand and pass. Findings while freezing: `@=` is not an operator, `0b`/`0o`/`r""` literals do not exist, and EOF errors now report the last line instead of line 0. Gaps: the fuzzer's invalid oracle is mutation-based, not a full grammar complement; the code-generating parser still accepts a few legacy forms beyond the grammar (it is not the one fuzzed).
4. `forge fmt` is a canonical formatter. Test: it is idempotent on all sources, and the repo is kept formatted in CI.
   - *Status: done.* `forge fmt [--check] [files]` (tools/fmt.forge, built to build/fmt on demand; no files = the repo set from `build/fmt --list` (tools/fmt_files.sh is the reference)) is a line/token-level formatter, so comments survive: 4 spaces per block level, continuation lines keep their offset from the opening line, single spaces between tokens, none after openers / before closers, commas and colons, one after a comma, two before an inline comment, no trailing whitespace, at most 2 blank lines, none at file start/end, one final newline; triple-quoted string contents are untouched. ## Phase 5 — Capability OS and sandboxing
*Pillars: A, D.*
1. **Handles replace ambient authority.** Every fd/proc/memory object is a capability with rights bits. Syscalls check rights, `dup` can only narrow them, and capabilities pass over IPC channels. Test: a child given a read-only handle cannot write; no global path lookup is possible without a directory capability.
   - *Status: done for file handles (console, files, directories).* Each fd carries rights (READ, WRITE, LOOKUP, DUP, XFER). read/getdents need READ and write needs WRITE. `dup(fd, rights)` (420) needs DUP and fails with EPERM unless the new rights are a subset. `openat(dirfd, path)` (421) needs LOOKUP and rejects absolute paths and `.`/`..`. `rights(fd)` is 422. open, stat and exec resolve only through the root-directory capability at fd 3; without it they return EACCES and the kernel logs `cap: pid N denied ...`. Rights survive fork and kexec, packed into the high half of the handoff fd slot. Test: `captest`, run by the boot shell script. Process and memory handles, and passing capabilities over IPC, come in 5.2.
2. **IPC channels** carry messages plus handles, with wait queues. Test: ping-pong latency is measured, and a handle is transferred.
   - *Status: done.* `chan(fds)` (423) creates two endpoint handles. `send(fd, buf, n, h)` (424) needs WRITE on the endpoint and XFER on h. `recv(fd, buf, n, &h)` (425) needs READ. A message holds 1–64 bytes plus an optional handle. The handle is moved, so the sender loses it and the receiver gets it in a free fd with the same rights. Each direction is a 16-slot ring; receivers and senders block on wait queues. recv returns 0 (EOF) once the peer's end is closed and the ring is empty. Channels come from a static 16-entry table, so none of the code needs `unsafe` beyond what the kernel already had. kexec refuses to run while any channel is open. Test: `chantest` does 2000 ping-pong round trips (about 9 ticks at 100 Hz under QEMU TCG, roughly 45 µs per round trip), refuses a handle without XFER, moves a file handle that the child reads but cannot write and echoes, and checks EOF after the child exits.
3. **Per-app sandboxes:** a manifest declares the capabilities an app gets (dirs, devices, network). The shell launches apps through the manifest. Test: an app that reaches outside its manifest is denied and logged.
   - *Status: done (files and dirs; no device or network grants yet, since there are no such handle types).* `sh: run APP [args]` reads `\EFI\Forge\apps\APP.mf`. Each `read PATH` line becomes a READ|DUP handle and each `dir PATH` line a READ|LOOKUP|DUP handle, on fds 4.. in manifest order; rights are narrowed in place with `restrict` (427). The shell then calls `exec_sandboxed` (426), which drops the root capability (fd 3) and marks the process sandboxed; its forked children inherit that. Each open, stat or exec outside the manifest returns EACCES and the kernel logs `sandbox: pid N (APP) denied OP PATH: not in its manifest`. kexec refuses while a sandboxed process is alive. Test: `run sbtest` reads its granted file (write and widening denied) and looks up inside its granted dir (`..` denied); open, stat and exec outside the manifest are denied and logged.
4. **Kernel hardening:** KASLR, stack canaries, guard pages per thread, and W^X for user ELF (already enforced for the kernel).
   - *Status: 5.4a (user W^X) done.* The ELF loader refuses any PT_LOAD that is both writable and executable, and refuses segments with different W/NX permissions that share a page (before, the first segment's flags silently won). Non-text segments, the stack, brk and mmap are NX. Test: the kernel feeds the loader a crafted RWX image and a mixed RX/RW page image (both refused, counted in `elf_wx_rejects`); `wxtest` forks children that execute data, mmap and stack memory and write their own text, and each dies with #PF (exit 0x10e).    - *Status: 5.4b (per-thread guard pages) done.* Kernel thread stacks (4 pages) come from `kstack_alloc` in their own bump VA range (`KSTACKS_BASE`, never reused) with an unmapped guard page below each. A thread that overflows faults on the guard page; the #PF cannot be pushed, so #DF (IST1) checks CR2 against the current thread's guard page and restarts the thread at `thread_overflow_exit` on the top of its own stack, which logs and exits it. Test: `guard_test` spawns an unbounded recursion thread; it is killed, the counter moves by 1, and all its frames come back.
   - *Status: 5.4c (stack canaries) done.* The freestanding compiler honours `# forge: stack-protector`: every function with a local or parameter wider than a word (array, struct) stores `stack_canary` at -8(%rbp) on entry and checks it before `leave`, calling `stack_smashed` on mismatch (33 kernel functions). The kernel seeds the canary from the TSC at the start of `kmain_high` (low byte zero). Test: `canary_test` runs a thread that copies 32 bytes past a 128-byte local buffer; the epilogue check catches it, the thread is killed and the kernel carries on.
   - *Status: 5.4d (KASLR) partial.* The dynamic kernel regions are randomized per boot: the big heap and the thread-stack range each start at a random 2 MiB slot (16 bits of entropy each, TSC-seeded in `canary_init`). The kernel image, the boot stack/IST stacks, the HHDM and the demand region stay fixed: moving the image needs a position-independent kernel plus relocation support in both loaders (GRUB multiboot2 and the Forge UEFI loader) and in kexec. Test: `os/kaslr` requires at least 5 distinct layouts across the 6 boots in tests/os/run.sh (3 first-generation kernels + 3 kexec'd ones).
   - *Status: 5.4e (image KASLR) done.* The kernel image itself now moves. It was already nearly position-independent (the freestanding backend emits RIP-relative addressing for symbols); the build links once with `ld -q`, `tools/krel.py` turns the remaining relocations (R_X86_64_64/32S into the high half, PC32 from the high half to the low boot stub) into a `.krel` table appended as the last segment, and the final image is linked without ELF relocation sections (GRUB refuses those). The kernel self-relocates, so the same mechanism serves GRUB (BIOS and UEFI), the Forge UEFI loader and kexec: `kaslr_pick` chooses a 2 MiB slide (about 500 slots, TSC-seeded, above the image size and below the fixed stacks at -1 GiB), `paging_init` maps the image at both KBASE and KBASE+slide, `krel_apply` patches it through the HHDM, `switch_stack` continues in the slid alias and `kaslr_unmap` drops the link-address alias. Test: `os/kaslr` also requires at least 5 distinct image bases over the 6 boots, the unslid alias unmapped in all 6, and the loader and the 3 kexecs reporting a relocatable kernel.

## Phase 8 — Real hardware and storage
*Pillar: F. Closes SYSTEMS.md items 1, 2, and 5.*

**Kernel infrastructure:**
- buddy allocator **(done)**: `mm.fsi` keeps the `frame_bits` used-map authoritative and adds per-order free-block bitmaps (orders 0..10, 4 KiB..4 MiB); blocks are re-validated against `frame_bits` on every take, so direct `frame_bits` edits (kexec grab, boot reserves) leave only stale entries that are dropped; the maps are rebuilt from `frame_bits` once if they run dry. `frame_alloc_contig(n)` takes an order-ceil(log2 n) block below 4 GiB (aligned) and returns its tail; `frame_free` coalesces. Boot test (`buddy_test`, all 3 boot paths and the kexec'd kernels): orders 0..10 come back aligned, 1000- and 3-frame runs work, 3050 frames held, everything coalesces back to the same number of 4 MiB blocks, 0 frames leaked. Gaps: contiguous requests are capped at 4 MiB (1024 frames); no per-CPU page caches; the kexec grab still scans `frame_bits` linearly.
- vmalloc **(done)**: the big kernel heap (`kmalloc` > 4 KiB) takes virtual ranges from a sorted, coalescing first-fit free list (`va_alloc`/`va_free` in `mm.fsi`, 256 slots) instead of only bumping; each range keeps an unmapped guard page. Boot test (`vmalloc_test`): 2000 mixed-size big allocations reuse VA (2000 reuses, high-water +183 pages, 1 free range left), 0 frames leaked. Gaps: list overflow drops a range (VA leak only); no `vmap` of arbitrary frames yet.
- PCID **(done, untested on hardware with PCID)**: `cpux.fsi` gives each address space PCID 1..63 per CPU and reloads CR3 with bit 63 (keep TLB) only if that CPU's slot still belongs to the same PML4. User shootdowns (on every CPU, including ones not running the space), `user_unmap` and `as_free` clear the PML4's slots, so the next load flushes. CR4.PCIDE is set only when CPUID offers it; the kexec stub clears PCIDE with PGE. Boot test: slot bookkeeping (hit, forget, collision) checked on every boot. Gap: QEMU TCG does not offer PCID and /dev/kvm is not accessible here, so the CR3-with-PCID path has not run; with PCID on, the boot panics if no switch ever reused the TLB.
- x2APIC **(done)**: `lapic_init` enables x2APIC (IA32_APIC_BASE bits 10+11) when CPUID.1:ECX[21] is set, on the BSP and every AP. `lapic_rd`/`lapic_wr` keep the xAPIC offsets as their interface and map them to MSRs 0x800+off/16; the ID read is shifted like xAPIC, and the ICR-high write is kept per CPU and merged into the single 64-bit ICR write (MSR 0x830), so callers are unchanged. No delivery-status polling in x2APIC mode. Boot test: x2APIC mode on all CPUs, IPI count via MSR 0x830 (QEMU TCG offers x2APIC). Unsafe ops at the 733 baseline allowance. Gap: APIC ids >= 256 are not handled (ID table is u8[256]).
- HPET/TSC-deadline **(done; TSC-deadline untested)**: `acpi_init` records the HPET block from the ACPI HPET table; `lapic_init` enables the main counter and times 10 ms of it against the TSC (32-bit counters masked), then uses the HPET value for the TSC and LAPIC timer rates (the PIT window is rescaled) and reports whether the PIT calibration agreed within 25% (not fatal: under a loaded emulator host the polled PIT window is skewed, which failed boots at O0). When CPUID.1:ECX[24] is set the LAPIC timer runs in TSC-deadline mode on every CPU: `lapic_wr(0x380, n)` becomes a write of TSC+n LAPIC ticks to IA32_TSC_DEADLINE and the timer handler re-arms it, so callers are unchanged; else LAPIC periodic. Boot test: HPET period line, timer mode line (panics if deadline mode armed fewer than 20 times). Gap: QEMU TCG `-cpu max` does not offer TSC-deadline, so that path has not run. Also reclaimed unsafe ops (PIC init from a table, kexec ELF headers read through `ptr[Phdr]`): kernel unsafe ops 733 -> 719.
- per-CPU run queues and load balancing **(done)**: `sched.fsi` keeps one FIFO per CPU (up to 8). `rq_push` puts a pinned thread on its CPU's queue and any other thread on the shortest queue; `rq_pop` takes from the local queue first and otherwise steals from the longest other queue (`rq_steals` counts). The single `rq_lock` is kept (it is held across `ctx_switch`, which keeps the no-double-run invariant), so this balances load but does not remove lock contention. Boot test: number of queues used and steals printed; panics if more than one CPU is online and fewer than 2 queues were used. Unsafe counts unchanged. Gaps: one global lock; no priorities; no cache-affinity heuristics beyond local-first.
- hardware drivers **(done except GOP console; xHCI mass storage, ICMP/UDP not done)**: `mmio.fsi` is the only place device registers are touched: `mmio_rd/mmio_wr/pio_rd/pio_wr` (the only `@unsafe` driver functions) check every access against registered windows (`mmio_add`, `pio_add`, `pci_map_bar` maps BARs uncached+NX, `dma_alloc` zeroed DMA pages) and panic on anything outside one; IOAPIC, PCI config and virtio were converted to them, and `drv_died` is no longer `@unsafe` (kernel unsafe ops 719 -> 676 in the counting pass). `pci.fsi` records every function (`pci_find`, `pci_find_id`, `pci_bar` with sizing). NVMe (`nvme.fsi`): admin + one polled I/O queue pair, Identify, READ only. AHCI (`ahci.fsi`): IDENTIFY + READ DMA EXT only. xHCI (`xhci.fsi`): reset, command ring (No Op), port scan, Enable Slot, Address Device, GET_DESCRIPTOR on EP0. e1000 and legacy virtio-net (`net.fsi`): send one ARP request for 10.0.2.2 and wait for the reply. No driver issues a write command to a disk. `hw_quiesce` resets all of them before kexec. Boot test `tests/os/drivers.sh`: q35 with nvme, ide-hd on AHCI, qemu-xhci + usb-kbd, e1000, virtio-net on `restrict=on` user netdevs; LBA 0 hashes must match the generated images, both images byte-identical afterwards, 0 out-of-window accesses. Gaps: no interrupts (all polled); no USB HID/mass storage class driver; no TCP/IP stack beyond ARP; not tested on real hardware; kexec with these devices present is not in the test.
- GOP console **(done)**: the UEFI loader walks the GOP mode list, sets 1024x768 RGBX/BGRX when offered (checks the SetMode status, else keeps the firmware mode) and reports the mode count and the chosen mode. The kernel console (`console.fsi`) is double-buffered at the cell level: `con_back` is what the screen should show, `con_front` what was drawn; a character draws only if its cell changes, and a scroll shifts `con_back` and `fb_flush` redraws only differing cells, so the uncached framebuffer is never read back (the old memcpy/memset scroll is gone). Boot test: before KERNEL OK the kernel checks back == front and that scrolling drew fewer cells than full redraws would (about 48% in practice), and the boot harness (`tests/os/boot.forge`, ported from boot.py) decodes the QEMU screendump and requires that line on the row directly above KERNEL OK on all three boot paths. Gaps: no mode setting from the kernel (BIOS path uses GRUB's VBE mode); no colours or cursor; no double-buffered pixel surface for graphics.
- writable Forge FS **(done)**: `tools/forge-part.py create DISK MIB --yes-add-forge-partition` is the only way a Forge partition is made: it validates the GPT, adds one entry with the Forge type GUID D0C2E3A1-6B7F-4F0A-9E11-466F72676546 in the largest free gap, rewrites only the primary/backup headers and entry arrays, and zeroes the new partition's first 4 KiB. The kernel (`ffs.fsi`) checks the GPT header and entry CRCs, requires exactly one Forge partition, inside the usable range, 4 KiB aligned and overlapping no other entry, then calls `nvme_claim(lo, hi)`; `nvme_write` refuses (and counts) any LBA outside that range, and without a claim the NVMe driver writes nothing. It formats only a blank (all-zero) superblock and refuses to format anything else. Layout: superblock (magic, version, size, generation, partition LBA, inode-table and superblock checksums), one 64-entry inode table, contiguous first-fit extents; commit order data -> flush -> inode table -> flush -> superblock -> flush. Data moves only through the registered DMA buffer and checked arrays; one new `@unsafe` helper reads string-literal bytes. Test `tests/os/forgefs.sh` (7 checks): a copy of the shared GPT disk (ESP + Windows + Linux partitions filled with data) as NVMe; boot without a Forge partition -> no writes, disk byte-identical; the tool refuses without its flag and keeps every partition identical; boot 1 formats and writes, boot 2 finds the files with matching hashes; after both boots everything outside the Forge partition (ESP, other partitions, GPT, gaps) is byte-identical; the host tool reads hello.txt back. The kernel also checks three out-of-range writes (LBA 0, just below and just above the partition) are refused. Gaps: NVMe only, 512-byte sectors only; flat namespace of 64 files, contiguous extents (no fragmentation handling), no journal (a torn inode-table write is detected by the checksum but not repaired); not exposed through the VFS/syscalls to user programs yet; the kernel never edits the GPT itself.

  - **9.2 status: done.** Every mutation in obj.fsi appends one self-checking record to a write-ahead log (type, object, blob with its words, version; each ends with an FNV of the record). Test: tests/fs/objlog.forge cuts the log at every word (638 cuts) and flips a bit in every word: every result is a consistent prefix of history (fingerprint equals the reference store at that timestamp), every corruption is detected, and writes after recovery survive the next replay. On disk (`examples/kernel/objd.fsi`): the log is the Forge FS file `objects.log` (64 blocks, reserved zero-filled, so it exists only on the explicitly created Forge partition and every write goes through ffs/nvme_write, which refuse anything outside it); each commit writes the log blocks it dirtied and flushes before returning. QEMU test os/objstore-crash-recover (tests/os/forgefs.sh): boot 1 creates the log, makes its durable commits (type, objects, 60 writes, each flushed) and then writes a torn version record; boot 2 recovers, drops the torn tail, reproduces boot 1's fingerprint exactly, reads back all 50 versions of object 0 at their timestamps, rewinds and commits again.

Test: tests/fs/objindex.forge, 100k objects: every lookup agrees with the linear scan, stays right after an update, a rewind and a replay, and indexed lookups are >= 50x (field; ~50 vs ~1.5M cycles) and >= 20x (full text) faster than scanning.
  - **9.4 status: done.** System rewind after a bad change, in QEMU (objd.fsi `objrw_test`/`objrw_verify`, tests/os/forgefs.sh boots 2 and 3): a typed system configuration lives in the store; a bad change to every slot is committed durably, the health check detects it, `sys_rewind` takes the whole store back to the last good clock (the bad versions stay in history) and the result is committed. Tests: os/objstore-system-rewind, os/objstore-rewind-persists.
  - **9.5 status: done.** Files as objects (examples/kernel/objfs.fsi): a file is an object (name hash indexed, name, size, up to 464 bytes of contents) and every write is a version; `/obj`, `/obj/<name>`, `/obj/@<clock>/<name>` and `/obj/@<clock>` are served read-only through open/stat/read/getdents (proc.fsi), with handles snapshotting their clock. Tests: tests/fs/objfs.forge, os/objfs-vfs-view, os/objfs-persists. Limits: files are at most 464 bytes and read-only through the VFS (writes go through the objfs API in the kernel); the QEMU test drives the kernel path resolver, not a userland open of /obj.

- untyped ints in the GC heap range — *Status: known limitation (documented, not fixed).* Dynamic (untyped) ints are raw 64-bit words, and the tag check (`rt_tag_r`, likewise `rt_gc_mark`) treats any 8-aligned value v with rt_hlo < v < rt_hp (heap at 0x200000000000, 64 GiB reserve) — or inside the data section for binaries not linked at `fld --base 0x100000000000` — as an object and reads its tag at -1(v). An untyped int that lands there is misread (TypeError, wrong output such as `[]`, or a crash). There is no safe local fix: an int equal to a live object's address is bit-identical to that pointer, so stricter checks (page table + slot alignment, a non-round heap base) only make collisions rarer and add work to the hot tag path; routing such literals through `__bigparse` does not help because the result is a raw int again. Typed `int` code is unaffected; the workaround is to type locals, parameters and returns that can hold such values (as done for pkg `rotr` and the lexer). The compiler still misreads a literal whose final value is an aligned address in its own live heap (e.g. 35184372088880), and hex literals in that range.

- post-kexec prompt race (inv80/g67 kernel HANG fix) — *Status: done.* Both kernel-bios and kernel-uefi stalled after `kexec next` (last line "kexec: input service state carried: …"). Root cause: `kx_restore` made the adopted shell runnable before `kexec_resume` restarted the input service (two slow kbdd image reads) and printed its report; those kernel `puts` are not under `con_lock`, so they interleaved character-wise with the shell's prompt (`shk$e xec`, `commitss hs$o  far` in the dumps). The harness counts literal `sh$ ` prompts, never saw it, never sent the next line, and the guest waited forever (CPU0 in `proc_reap`'s yield loop, APs idle — not a scheduler/LAPIC bug; timer re-arm, EOI and irq_save balance checked). Fix: `kx_restore` calls `kexec_input_resume()` (kernel.forge) before any adopted thread becomes runnable; it sets `kb_svc = 1` first (input queues behind the carried journal entries, so they replay before any new tty input), seeds `kbd_shift`/`kbd_e0` from the carried decoder state, reads the images, starts kbdd and prints the report. Regression: boot.forge `FORGE_BOOT_KEXEC=N` repeats the handoff with serial and keyboard input sent the moment each new prompt appears; the post-kexec session keeps the test hooks so the shell can hand over again; run.sh's kernel-bios does 3 handoffs ("kexec: generation 3 kernel adopted", KASLR counts follow `KXR`). Reproduction: 6 single-kexec boots on old HEAD (idle and under host load) did not hang, but 4/6 logs showed kernel lines landing right after the post-kexec prompt (the window is real; it hangs only when the split falls inside `sh$ `). Fixed tree: 5/5 boots that reached the shell went through 3 handoffs with no interleaving. Dumps: /workspace/hang-dumps/inv80.
- FIXED (was KNOWN OPEN ISSUE): livepatch stop_machine/tlb_poll rendezvous deadlock — *Status: fixed.* Under host load the stop-machine initiator waited forever on `tlb_acks` while every other CPU sat parked in `tlb_poll` (IF=0). Root cause: `spin_lock` calls `tlb_poll` with interrupts on, so a timer tick inside the poll could reschedule the thread to another CPU (dumps show the timer firing inside `lapic_cpu()` in `tlb_poll`, then the TLB IPI nested inside that). The migrated thread answered and parked for the first CPU's request, and the stray answer was counted by the single shared ack counter against a later round, which finished early. Fix (examples/kernel/cpux.fsi): `tlb_poll` runs with interrupts held off and a per-CPU `tlb_in_poll` flag, so a nested entry leaves the request to the outer poll. The shared counter is replaced by per-round generations: the initiator bumps `tlb_gen` and posts it to `tlb_req_gen[c]`, each CPU answers by storing the round it served in `tlb_ack_gen[c]`, and the initiator waits until every `tlb_ack_gen[c] == tlb_gen`. The park loop keeps answering newly posted requests while it waits. The lapic timer handler was checked: it EOIs, then takes `rq_lock` and calls `schedule_l`, but a parked CPU has IF=0, so the handler never runs while parked. Regression: kernel self-test `stop_machine_stress` (kernel.forge), in which 3 threads hammer a contended spinlock with interrupts on while the test thread runs 3000 stop-machine rounds; marker `stop_machine stress OK: 3000 rounds` in tests/os/run.sh. Before the fix, 3 of 3 loaded boots hung in this test; after it, 5 of 5 pass. Dumps: /workspace/hang-dumps/kxfix6 and /workspace/hang-dumps/smx.

- Exact `__powfits` (float literals 1e16..1e22, typed `**`) — *Status: done.* Found while probing c2forge step 5: `e: f64 = 1e17` made forgec fail with `line 0: integer overflow`. The compiler folds a float literal with `float(text)`; `__fparse`'s Clinger fast path (<= 15 digits, |e10| <= 22) scales by `__ipow(10, k)`, and `__powfits` approximated the overflow test as bits(|a|) * b <= 62, so 10**16..10**18 (which fit) were rejected, and so was every typed-int `a ** b` past that bound. It now multiplies step by step against 2**62 - 1, the small-int limit (at most 62 steps for |a| >= 2); a first draft bounded by 2**63 - 1 let 2**62 .. 2**63 - 1 take the small-int path, which tests/bigints.forge (O2 and ast-pretty-semantic) caught: `2 ** 62` printed garbage and sums of it lost their bigint promotion. Regression tests/pow_fits.forge (typed powers up to 10**18, 3**39, 2**61, 7**22, and `2 ** 62` .. `2 ** 63` staying exact as bigints; literals and `float()` of 1e16..4e22). Two-pass reseed (prelude change), pinned in seed/seed.sha256 and reproduced byte-for-byte by build.sh (SEED OK, SEED TOOLS OK).
